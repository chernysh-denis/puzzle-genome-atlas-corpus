## Decision structure

The player sees exact input and output assemblies, configures a spatial
machine and writes synchronized per-mechanism instruction tapes. A committed,
resettable automatic run must repeatedly carry source material into exact
accepted products without a kinematic conflict. Failures return the player to
the design rather than becoming another direct move inside the run.

## Combination match boundary

A construction or programming game does not instantiate this combination
merely because it automates movement. The player must author both persistent
spatial machinery and aligned symbolic mechanism schedules before a separate
automatic run; exact input/output structure and repeated product acceptance
must be disclosed; kinematic conflict must invalidate execution. Live editing,
direct unit commands or a one-off unstructured destination fall outside the
boundary.

## Decision structure

The player sees exact supplied and required assemblies, places persistent
machine components under footprint-compatibility rules and commits the layout
to a separate resettable automatic run. A recurrent source and exact sink force
the spatial design to produce the declared assembly repeatedly rather than
deliver one arbitrary payload.

Both games also share `INF-001` and `OBJ-016`, but generic current-state
visibility and optional optimisation do not define the exact-output factory
interaction.

## Combination match boundary

A construction game does not instantiate this combination merely by moving
items automatically. Exact input / output assembly schemas must be visible;
the player must configure persistent spatial machine components; placement
compatibility must affect the design; and a separate resettable run must feed a
recurrent source into an exact sink until a repeated-output quota is met.
Symbolic tapes, conveyor fields, transformation devices and optimisation
metrics may differ outside the shared core.

This combination is nested beside, not substituted for, `COMB-0032`.
`COMB-0032` requires synchronized symbolic cyclic execution and kinematic-
conflict invalidation but does not require component placement. `COMB-0042`
requires component placement and static compatibility but does not require a
symbolic controller.
